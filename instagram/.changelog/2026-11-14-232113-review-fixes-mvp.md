# Engine-neutral chat keys and no repeated sends

Problem ID: instagram-applet · Spirit animal: 🦩 Flamingo

- Goal: make the applet work the same on both website engines and pass `check`, never send a message or post a comment twice after an uncertain tap, and stop stale state from acting without a tap.
- Changes: inbox rows are keyed by the chat's title and picture again; the page module no longer reads the props React keeps on Instagram's elements, which GeckoView cannot see and `check` now refuses. `sendMessage` reads the message box first: it types only into an empty box, only presses Enter when the box already holds the same text, and refuses when it holds other text. After an unknown outcome, Send and Post stay off until the text is edited or the chat or comments show it. The "+" request from Following or Favorites expires after 15 seconds. The Profile tab forgets the account once the session reports a sign-out. Show more tells the end of the list, Instagram's rate limit and other failures apart.
- Decisions: chat keys are not stored anywhere (decision-0008), so the key change affects only the current session's rows. The "+" request stays outside the screen, which mounts again for the new page, with a deadline instead of a ref.
- Verification: `check`, `typecheck` and `build` pass. No device was used; every change is implemented, not device-verified.
