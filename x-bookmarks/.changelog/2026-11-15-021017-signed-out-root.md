# Signed-out X opens sign-in, not the landing page

- Goal: Signed out, the applet opened x.com's "Get the app" landing page under a "no screen for this page" banner, because X redirects `/home` to `/`, which had no route.
- Changes: A `root` route maps `/` to the Home screen in `primary`, needing the account; Home's kind and the Home tab treat `/` as `/home`. The account reader also counts a page with no `main` and a Sign in link (`/i/jf/onboarding/web?mode=login`) as signed out, since the landing page has no `loginButton`; requiring no `main` keeps a signed-in page that links to sign-in from counting. Done on that sign-in page now leaves the applet, through the SDK router. Skeleton rows fade in after 120 ms and shimmer with a new `--shimmer` token.
- Decisions: decision-0011.
- Verification: `check` and `build` pass. On the Samsung SM-M307F, signed out, with the Genesis debug build of `fix/applet-ux-polish`: opening X shows the Home skeleton, then X's sign-in page under the info banner "This page opens on the website. Done takes you back to X." Done there returns to the Genesis launcher. Signed-in Home was not rechecked: sign-in is blocked by X's errors on the test account.
