# Media grids and the photo viewer on the phone

Problem ID: applet-revamp
Problem: Revamp every applet with the native-feel guidance
Spirit animal: 🦉 Owl

- **Found on the phone (RZ8N20D84GX):**
  - Search Media fell back to X's page. X renders that tab as `li[role="listitem"]` tiles linking to `/status/<id>/photo/<n>` or `/video/<n>`, with no posts, so the explore page never became ready.
  - Profile Media showed blank play tiles for video posts, flashed "No photos or videos yet" before X rendered the section, and replaced the header with the full profile skeleton on each section switch.
  - The media viewer showed disabled Previous and Next for a single photo.
- **Changes:**
  - New `tiles` list reader (`readTile`, keyed by link) and `MediaTile` model. Explore readiness accepts tiles, `loadMore` scrolls to the last tile, and a `TileGrid` renders them in explore and profile. A photo tile opens the viewer; a video tile opens the post.
  - Posts read the first video's `poster`, so the profile grid shows a preview with a play badge.
  - The profile keeps its header while a section loads. An empty section shows the empty notice only when X shows its empty state, or after the list has stayed empty for 5 seconds on a fresh page.
  - The viewer shows Previous and Next only when the post has more than one photo.
- **Review fixes:**
  - A missing or suspended profile shows X's empty text with View on X instead of the skeleton forever.
  - The media viewer shows "This photo couldn't be shown" with View on X when the page is ready and reads no photo.
  - The Profile tab shows the load error when the account page is ready and reads no handle.
  - Saved categories reset the filter and search to the defaults when the library changes, before its stored preferences apply.
  - "No replies yet" waits until the replies stay empty for 5 seconds; `useSettled` moved to `screen.ts` for the post and profile screens.
  - Reselecting a tab scrolls without smooth motion under reduced motion.
  - The tab bar is hidden while a sheet is open, as the spec says, so it no longer takes taps behind the sheet.
  - A saved post's text is a keyboard-operable button by role.
  - `Avatar` and `FadeImage` start over when their `src` changes.
  - The explore search field shows the current query when it changes while the field is not focused.
- **Verification:** `npm run check`, `npm run typecheck` and `npm run build` pass. On the phone: search Media renders the grid, a tile opens the viewer and Close returns to the same grid; NASA's profile Media keeps the header, shows the grid skeleton, then the posters; a single photo shows no paging buttons.
- Review fixes re-checked on a phone: the Profile tab shows the signed-in account after its skeleton, and Home loads its feed. The error and missing-profile paths were not reproduced on a device.
