# Keep the account address during a reload

- Goal: Fix finding 3 of the [open SDK migration review](../.specs/review-open-sdk-migration.md): an item saved while Gmail reloads got the account "unknown", and account dots flickered. Finding 1, Back from the inbox leaving the applet, needs a phone check and is left open; finding 2 is an SDK problem being fixed in the SDK.
- Changes: `src/store.ts` keeps the last address the `view` watch showed as the current account until the page shows another, as the old store's account did. The session index is still taken only while the page shows an address, so a reload's URL never renumbers the previous account. After a pull request review, the conversation's More menu item "Gmail Only settings" only navigates (`src/screens/conversation.tsx`): it used to close the menu in the same click, and the menu's cleanup then went Back and closed Settings at once. The menu now closes itself when Settings becomes the current screen, as its other links do. That was not enough: Settings is a full screen, so the conversation and its menu unmount in the same render, and the menu's cleanup still saw its own screen as current. The shell now records the router's current screen key on each render (`shownScreen` in `src/components/ui.tsx`), and the menu's cleanup goes Back only while that live key is still the menu's.
- Decisions: none; this restores the behavior decision-0015 kept.
- Verification: the applet's `typecheck`, `check` and `build` pass. Not run on a device.
