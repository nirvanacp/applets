## decision-0002: One context, Discord's app layout

- Date: 2026-11-17.
- Origin: builder, for the user's request of a mobile-friendly Discord applet.
- Choice: one context `primary` that starts at `/channels/@me`. Discord is one single-page app with one gateway connection per page; a second context would load it twice. Messages is a routed screen for `/channels/@me`; Servers is an overlay screen that reads the server rail of whatever channel page is current; a server opens its last channel (`/channels/<guild>`, which Discord redirects), as Discord's Android app does; the server's channel list is an overlay sheet over the chat, read from the same page.
- Affects: routes `messages`, `dm`, `channel`, `guild`; screens `servers`, `channels`.

## decision-0004: Sending with trusted input

- Date: 2026-11-17.
- Origin: builder.
- Choice: Discord's composer is a Slate rich-text editor, which ignores synthetic editing. `send` types each line with trusted input, presses Shift+Enter between lines and Enter to send, and waits for the `sent` reader: the editor is empty and the newest message holds the text. The text is limited to 2000 characters, Discord's own limit and the limit of one trusted `type`. When Discord's editor already holds a draft the user typed on the website, the applet does not overwrite it and offers the website instead.
- Affects: interaction Chat: Send; one tap sends once, never repeated after `unknown`.

## decision-0006: Discord's phone layout: the drawer and the channel from the rows

- Date: 2026-11-17.
- Origin: builder, from the signed-in page on the emulator.
- Finding: at phone width Discord draws the server rail, the direct-message list and a server's channel list only inside a drawer, and a server's URL stays `/channels/<guild>` without the channel id.
- Choice: the Messages, Servers and Channels screens open the drawer once per page view with `openDrawer` and report a failure instead of retrying. The chat takes its channel from the URL, or else from the message rows (`chat-messages-<channel>-<message>`); `ready.chat` is true on a server URL as soon as rows exist. Rail entries without a numeric id (Home, Add a Server, Discover, the app download) are not servers. An author's name comes from the username's `data-text`, which leaves out the server tag.
- Affects: routes `guild`, `channel`; screens `messages`, `servers`, `channels`, `chat`.

## decision-0007: Sending with fill and click, confirmed by a new message

- Date: 2026-11-17.
- Origin: builder. Supersedes the typing method of decision-0004; the draft and limit rules of decision-0004 stand.
- Choice: Discord's phone composer is a plain `textarea`, so `send` fills it and clicks Send Message; on the desktop Slate editor it still types with trusted input. Before sending it scrolls Discord's list to the newest message. It counts as observed only when a message id that was not in the list appears last, was created no earlier than two minutes before the tap (the id's snowflake time), holds the first line of the text (or, without text, an attachment), and the editor and uploads are empty.
- Affects: interaction Chat: Send; one tap sends once, never repeated after `unknown`.

## decision-0011: Media grid, viewer and loading titles

- Date: 2026-11-17.
- Origin: builder, from the phone.
- Finding: the media reader matched both a mosaic item and its content child, so every picture showed twice; Tenor and other linked GIFs are `inlineMediaEmbed` blocks whose player Discord mounts only on screen, so those messages showed empty; during a channel switch the page reports the place before its name, so the title read "#".
- Choice: the reader takes only the outermost mosaic item, drops repeated addresses, and also reads linked media from the original link's `data-safe-src`, only on Discord's own media and proxy hosts. A message shows at most four tiles with "+N" on the last; the viewer holds all of the message's media and pages with arrows, arrow keys and a swipe. A GIF tile plays muted on a loop while on screen and pauses off screen (the WebView does not autoplay by itself); with reduced motion it keeps its first frame. Until the page names the place, the chat title shows the name of the tapped row, kept by path in memory for 50 paths.
- Affects: screens `chat`, `messages`, `servers`, `channels`; reader `messages`.

## decision-0012: Message actions, replies and quick reactions

- Date: 2026-11-18.
- Origin: user, 2026-11-18: "I'm not able to sent messages or reply." Changes the exclusions "no new reactions beyond the ones a message already shows" and "message menus on the website".
- Finding: on the account's own messages Discord's hover toolbar has no Reply button, only Add Reaction, Edit, Forward and More; the toolbar takes pointer events only under real CSS `:hover`, which a synthetic hover does not set; while a message sends, Discord shows a row with a temporary id, which the virtualized reader kept beside the real row.
- Choice: a tap on a message opens a bottom sheet with a preview, six quick reactions (👍 ❤️ 😂 😮 😢 🔥), Reply and Copy text. Reply goes through the message's More menu (`#message-actions-reply`) for every message; reactions use the chip when it exists, otherwise the Add Reaction picker searched by the emoji's name. Toolbar buttons are clicked with `force` after a hover. Rows marked as sending are not read. A reply belongs to its conversation and clears when the channel changes.
- Affects: interactions Chat: message row, Actions: quick reaction, Reply, Copy text, Chat: Send; commands `send`, `addReaction`; reader `messages`.

## decision-0013: Profile, status and server editors in the applet

- Date: 2026-11-18.
- Origin: user, 2026-11-18: "check everything from uploading a profile picture, changing names, renaming, and interacting with settings … Everything should work at the end". Changes the preserved website workflow "profile editing" and part of "settings".
- Finding: Discord keeps these editors in dialogs on the same page: "Your full profile" (picture, display name, pronouns, bio) from the user area's popout, the per-server profile and Server Settings from the server header's menu (`#guild-header-popout-<item>`), the status menu (`#set-status-submenu-mobile-web-<status>`) and User Settings. Each saves through a bar with Reset and Save that appears only while it has unsaved changes, and none closes while that bar shows. The user area is drawn only while the drawer is open.
- Choice: a third tab, You, shows the account from the user area with Edit profile, Status (a sheet of Online, Idle, Do Not Disturb, Invisible) and Settings on the website. The channel sheet gets a server menu: Edit server profile (nickname) and Edit server (name and icon) are applet forms; Invite people, Notification settings and Server settings show Discord's own dialog on the website and return to the channel sheet on Done. Each form opens Discord's dialog when it mounts, fills only what changed, presses Discord's own Save, and counts as saved only when Discord's fields show the new values and the save bar is gone. Leaving a form resets unsaved changes on Discord and closes the dialog. Pictures come from Android's picker and go through Discord's crop dialog unchanged. Fields over Discord's limits (32, 40, 190, 100 characters) disable Save, since an Android keyboard can commit text past `maxLength`. Deleting or disabling the account, deleting the server, and removing the avatar or icon stay on the website.
- Affects: screens `you`, `profile`, `nickname`, `server`, `channels`; readers `me`, `profile`, `serverProfile`, `serverSettings`; commands `openProfile`, `saveProfile`, `setStatus`, `openSettings`, `openServerItem`, `openServerProfile`, `saveNickname`, `openServerSettings`, `saveServer`, `dismiss`.

## decision-0014: Driving Discord's editors reliably

- Date: 2026-11-18.
- Origin: builder, from failures on the emulator.
- Finding:
  - The profile editor shows its fields as text and takes a change only while the field is being edited, which starts with focus; a `fill` without focus is dropped.
  - The bio is a Slate editor that opens from an empty "Edit bio" box. Trusted typing at phone width takes the placeholder in as text; trusted input refuses Control with a letter, so Ctrl+A cannot select the old bio; Discord keeps the bio only when focus moves to another field, not on a plain blur.
  - The avatar crop dialog enables Apply before its canvas has drawn the image, and an early Apply changes nothing. The server icon crop dialog has no canvas, only an `img`, and plays an opening animation (opacity 0 and `scale(0.9)` to 1 over about 325 ms); an Apply pressed during it saves an empty image (`data:,`, "Only base64 encoding can be used").
  - A covered (hidden) page pauses Discord's timers and animations, so crops and closing layers stall until the page is awake.
  - Settings ignore a synthetic Escape, which has no key code. Server Settings draws its close controls as `div[role=button][aria-label=Close]`, not buttons, so a close step that looked only for buttons left the dialog open and the next menu tap failed with "The target is covered".
  - An empty channel's only row is Discord's welcome block, a `div` with the channel id, not an `li`.
- Choice: fields are filled with focus, fill and blur. The bio is typed line by line through editing commands, the old text is selected with Ctrl+End and Ctrl+Shift+Home, and focus moves to the pronouns field before Save. Apply waits for `profile.cropReady`: the crop is drawn (canvas with a width, or a loaded `img`) and no box in or around the dialog is still below full opacity or scale. A save with a picture holds the page awake. Closing clicks the top layer's own Close, matching `button` and `[role=button]`, then presses Escape for the rest. The chat's channel check reads any element with a `chat-messages-` id.
- Affects: commands `saveProfile`, `saveServer`, `dismiss`; reader `profile.cropReady`; reader `place` and `ready.chat` in empty channels.

## decision-0015: Show kept pages first, keep nothing on the phone, window a long server list

- Date: 2026-11-18.
- Problem ID: `applet-performance` · Problem: Find what makes page switches, loads and like/save actions lag in the built applets · Spirit animal: 🐆 Leopard
- Origin: agent choice while upgrading the applet to Genesis's runtime speed work.
- Choice: screens keep drawing content whenever there is data, fresh or kept, and read empty and failed from the watch's data state (`watchStatus`).
- Choice: no watch sets `persist`. Chats hold message contents and are never kept. Messages, Servers and the channel list hold only names and status lines, but they are read from Discord's drawer, and each screen shows rows only while the drawer is open; on a fresh start the drawer opens after the page is ready, so kept rows would give way to a skeleton and come back. Keeping them first needs a change to how these screens wait for the drawer, checked on a device.
- Choice: when the router reports no account and the applet last saw one, the applet calls `forgetCached`. It remembers only "signed in" or "signed out" in its own storage, so a signed-out start does not forget each time.
- Choice: the server list uses `VirtualList` once it passes 50 servers; every row has the same height. The chat stays a plain list: it is anchored to the newest message, keeps its distance from the bottom while older messages load above and while the keyboard opens, and its rows vary with pictures and replies. Messages and the channel list stay plain: Discord draws only the part of its drawer near the view, so they stay near one screen of rows.
- Affects: Messages, Servers, channel list, chat, sign out.
