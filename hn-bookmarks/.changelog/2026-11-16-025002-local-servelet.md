# Bookmarks in a local servelet

Problem ID: let-servelets
Problem: Move the applet framework into Let, add servelets that run on the phone, and move the Hacker News bookmarks backend to one
Spirit animal: 🐙 Octopus

- Goal: Run the `bookmarks` service on the phone as the `hn-bookmarks` servelet, so Saved works without a computer, a tunnel or a token. The service id, endpoints, collections and record shapes stay the same, so the applet's UI code is unchanged.
- Changes: `service.json` declares `runtime: local` with servelet `hn-bookmarks` from the servelets collection; `applet.json` names it. The Node backend moved to `legacy/backend/` with a README; the build does not use it. The `backend` script is gone, `ports.json` reserves no port, and `start.sh` stays as the collection's launcher stub and reports that no backend is required. The README operator setup and the current spec say the data lives on the phone. In Genesis, the host now answers a local service from the servelet bundled with the revision, keeping its SQLite database in the app's private storage.
- Decisions: decision-0015.
- Verification: passed on the emulator Genesis_Verify_API_37 (emulator-5554) and, up to the force stop, on the developer's phone; details and timings in the current spec, "Current work and verification". Clear data and Remove were checked on the emulator only.
