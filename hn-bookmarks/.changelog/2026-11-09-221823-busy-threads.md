# Busy threads

- Goal: Show busy HN threads in the applet instead of a load error and the website (plan finding F9). A front-page thread of 1,105 comments was past the 192 KiB page limit.
- Changes: The `comments` region reads the first 200 comment rows. A new `rest` region counts the rows after them, and its `showRest` page action scrolls HN's page to the first of them. The item screen ends with "Read N more comments on Hacker News", which runs the action and then shows the website. Search hides Next page when the site shows a single page; its pagination list is there even then.
- Decisions: decision-0008. A `virtualized` region could not help, because HN keeps every comment in the DOM.
- Verification: `typecheck`, `check`, `build` and `npm test` passed. On a Samsung SM-M307F, with dev revision 7: the 1,105-comment thread showed 200 comments; the button opened HN at comment 201; Done returned to the applet; Hide and Show worked; Back from a profile kept the scroll. A single-result search showed no Next page. Not measured: the largest published page size. A thread of 200 very long comments may still pass the limit.
