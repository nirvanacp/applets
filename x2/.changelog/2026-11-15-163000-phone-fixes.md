# Fix what the phone check of X2 found

Problem ID: x2-applet
Problem: Rebuild the X applet with the native-feel guidance
Spirit animal: 🦊 Fox

- **Goal:** fix the defects a signed-in phone check found in X2, and those a self review of the applet found.
- **Phone check (before these changes):**
  - Worked: cold start with skeletons, the five tabs, post detail with Back keeping the scroll, the website cues, the composer and its Discard dialog, the Save and Manage sheets above the keyboard, and create and delete in Manage.
  - Failed: the four defects below.
- **Changes:**
  - Empty states: the title reads X's heading element, or the first rendered line, instead of the whole text, which ran the heading into the explanation ("Save posts for laterBookmark posts…").
  - Media viewer: it pages through the photos of the post it was opened from, so Next works on the first photo and Close no longer reloads Home (decision-0006). The page reader picks the centred photo relative to the viewer, not the window, and falls back to the nearest one.
  - Categories:
    - One reload count is shared by every screen, so a change in the Manage sheet refreshes the Categories screen behind it.
    - A change whose outcome is unknown no longer leaves a second warning in the sheet after "Check last change". A create that the check confirms clears its name from the field.
    - Load more from an older filter or search is dropped.
  - README: `--device <adb-serial>` restores the phone tunnel after a reboot.
- **Not fixed:**
  - Why the first create reported an unknown outcome although the service committed it. The service returned the receipt afterwards, and the next change (delete) settled normally.
  - The post-detail skeleton shows a photo block for every post.
  - The feed has no view counts.
- **Verification:** `npm run check`, `npm run typecheck` and `npm run build` pass. The fixes were not run on a device: phone use ended with the check task, and the emulator could not sign in to X.
